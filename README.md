## 🚀 Getting Started

**Prerequisites:** Flutter 3.47.6, a Firebase project with Firestore + Auth enabled.

```bash
# 1. Clone
git clone https://github.com/0xCoderunknown/dreamfluenzer-erp.git && cd dreamfluenzer-erp

# 2. Install dependencies
flutter pub get

# 3. Set up Firebase (pick one):
#    Option A — automatic (recommended):
dart pub global activate flutterfire_cli
flutterfire configure
#    Option B — manual: copy the example and fill in your keys
cp lib/firebase_options.dart.example lib/firebase_options.dart

# 4. Configure your local agency settings:
cp assets/config/config.demo.json assets/config/config.json
# Edit assets/config/config.json with your agency details. Never commit it.

# 5. Run
flutter run -d chrome
```

See [`CONTRIBUTING.md`](CONTRIBUTING.md) for a full setup guide.

## 🏗️ Architecture & Philosophy

Built on Clean Architecture with strict layer isolation:

```text
lib/
├── config/        # Human operator surface (agency constants & runtime config)
├── domain/        # Pure domain invariants (FroyoRules, AppEnums)
├── engines/       # Pure Dart computation (RevenueEngine, DashboardAuditor)
├── models/        # Immutable schemas & Firestore DTOs with copyWith
├── providers/     # Reactive state (ChangeNotifier) & atomic Firestore transactions
├── router/        # GoRouter navigation & auth guarding
├── screens/       # Top-level responsive views
├── services/      # I/O wrappers (Firestore, AuditLogger, PDF builders)
├── theme/         # Design tokens & status color resolvers
├── utils/         # Pure validators & formatters
└── widgets/       # Reusable presentation components
```

### Key Invariants

* **Twin Budget Principle** — Liquid cash (`baseBudget`) and Barter GMV (`gmvBudget`) are parallel, strictly isolated ledgers. They are never summed.
* **Froyo Rules** (`lib/domain/froyo_rules.dart`) — Two non-negotiable financial guards:
  1. **Archive Lock:** A project cannot close if creator deliverables are in-flight or live work is unpaid.
  2. **Advance Safety Net:** Creator advances cannot exceed the client advance pool for that project.

### Tech Stack
| Layer | Technology |
|---|---|
| Framework | Flutter / Dart (web-first) |
| Backend | Firebase (Cloud Firestore) |
| State | Provider (`ChangeNotifier`) |
| Routing | GoRouter |
| PDF Generation | `pdf` + `printing` packages |

## 🔐 Credential System

Private credentials **never** touch the repository:

| File | Status | Purpose |
|---|---|---|
| `assets/config/config.json` | 🔴 gitignored | Your real Firebase keys + agency details |
| `assets/config/config.demo.json` | ✅ committed | Generic demo values for contributors |
| `lib/firebase_options.dart` | 🔴 gitignored | Generated by FlutterFire CLI |
| `lib/firebase_options.dart.example` | ✅ committed | Template for manual setup |

The app loads `config.json` at runtime. If absent, it falls back to `config.demo.json`.
`lib/config/agency_config.dart` supplies safe defaults; deployment-specific values
belong in the ignored local JSON file.

## 🤖 AI Maintenance

This repository is designed for **100% AI-driven maintenance**. Agency operators manage
deployment-specific values in their ignored local `assets/config/config.json`; AI
maintainers own application code and follow [`AGENTS.md`](AGENTS.md).

Before submitting a change, run `dart run tool/verify_invariants.dart`. It checks
formatting, presentation file sizes, repository source/config secrets, analysis,
and tests.
